Confirmed findings

Issues found by reading the actual code, not assumptions. Ordered most to least severe.

1. Dashboard always shows Level 0, even after it's finished bug

Dashboard.tsx reads progress.currentLevel to pick which level's title, progress ring, and "next lesson" CTA to show. But useProgress.ts never updates currentLevel anywhere — it's set once at init and completeLesson() never advances it. A user who finishes all of Level 0 and unlocks Level 1 will still see the Dashboard pointing at Level 0 lessons; the only way to reach Level 1 content is via the Learning Path tab.

src/hooks/useProgress.ts — completeLesson() · src/pages/Dashboard.tsx:16

2. One badge can never be earned dead logic

The "7-Day Journey" badge (week-streak, awarded at a 7-day streak) is defined in data/lessons.ts and shown on the Profile page, but no code path ever adds week-streak to earnedBadges. Streak increments happen in the useProgress initializer, with no badge check attached. Of 8 total badges, this one is permanently stuck at "not earned."

src/data/lessons.ts — badges[] · src/hooks/useProgress.ts (no streak-badge check exists)

3. Badge logic is hardcoded to levels 0–1 only scalability gap

completeLesson() hardcodes the lesson-id arrays for level 0 (level0Lessons) and level 1 (level1Lessons) to award the level-1/level-2 badges. Finishing Level 2 or Level 3 triggers no badge at all — not because none is designed (the data file only defines 2 level badges by design), but because any future level badge would require another hand-written array rather than deriving from levels/lessons data.

src/hooks/useProgress.ts — completeLesson()

4. Cloud sync is not partially done — it's 0% done confirmed via code search

A repo-wide search for supabase.from( returns zero results outside auth. Every one of completed_lessons, journal_entries, user_achievements, user_reading_progress, quiz_answers, lessons, achievements, bible_plans is unused by the frontend. This matches what the docs already flagged as a known gap — confirming it is accurate and total, not partially mitigated somewhere else in the code.

repo-wide search: supabase\.(from|auth) — only auth.* calls found

5. Orphaned scaffold page cleanup, no user impact

src/pages/Index.tsx is the default Lovable/Vite "Blank App" placeholder page. It is not imported by App.tsx and not reachable by any route — dead code left over from project scaffolding.

6. requiredXp on each level is unused cleanup, no user impact

Each entry in levels[] carries a requiredXp field (100/200/250/300), but level unlocking in LearningPath.tsx is based entirely on lesson completion, never on XP. The field is inert — either remove it or decide XP-gating is a real future rule and wire it in.
