Where state lives today

The gap between what the UI shows and what the backend persists is the central technical fact for sprint planning.

Live today localStorage

  • useProgress() reads/writes key faithjourney-progress
  • completedLessons, xp, currentLevel, journalEntries, streak, quizAnswers, readingPlans, earnedBadges, userName
  • Badge logic runs client-side inside progress actions
  • Streak logic: same day → keep, yesterday → +1, else → reset to 1 (timezone-naive)
  • Static content served from src/data/lessons.ts, not the DB

Ready but unused cloud DB

  • Schema exists in Supabase: completed_lessons, journal_entries, user_achievements, user_reading_progress, quiz_answers
  • profiles row auto-created on signup via handle_new_user trigger
  • lessons, quiz_options, achievements, bible_plans tables already seeded with content
  • No sync layer yet — nothing written here from the app except auth + profile creation
  • No hydrate-on-login step — a user's progress does not follow them across devices
